# SSH 反向隧道清理指南：如何将本地与远端恢复原始状态

## 📖 背景与目标

**目标**：彻底清理之前为建立 SSH 反向隧道所做的所有配置，将本地 Windows 和远程 VPS 恢复到初始状态。

**适用场景**：

- 不再需要通过 VPS 访问本地服务。
    
- 准备重装系统或迁移服务器。
    
- 发现隧道存在安全隐患，需要彻底关闭。
    

**清理原则**：

1. **先停服务，再改配置**，避免连接中断导致无法操作。
    
2. **双向清理**：本地 Windows 和远程 VPS 都要恢复。
    
3. **验证闭环**：清理后必须确认端口已关闭、公钥已移除、服务已禁用。
    

---

## 第一阶段：停止并移除隧道进程与服务

### 1.1 关闭正在运行的隧道

**如果是手动命令行运行**：

- 直接关闭本地 Windows 上运行 `ssh -N -R ...` 的 PowerShell 窗口。
    
- 或者在窗口中按 `Ctrl + C` 终止 SSH 进程。
    

**如果是 MobaXterm 等图形工具**：

- 关闭对应的 SSH 会话标签页。
    
- 退出 MobaXterm 程序。
    

### 1.2 停止并移除 Windows 服务（如果使用了自动重连工具）

如果你之前用 TunTun、Rospo、NSSM 等工具注册了 Windows 服务，必须先停止并卸载它们，否则它们会不断尝试重连。

**以管理员身份打开 PowerShell**：

**情况 A：使用 TunTun**

powershell

tuntun.exe stop
tuntun.exe uninstall
# 删除配置文件
Remove-Item -Path "C:\ProgramData\TunTun" -Recurse -Force

**情况 B：使用 Rospo**

powershell

# 如果注册为服务，先停止服务
Stop-Service -Name "Rospo" -ErrorAction SilentlyContinue
# 卸载服务（具体命令取决于 Rospo 的安装方式）
rospo.exe service uninstall

**情况 C：使用 NSSM**

powershell

# 停止服务
nssm.exe stop SshReverseTunnel
# 移除服务
nssm.exe remove SshReverseTunnel confirm

**情况 D：使用其他自定义服务**

powershell

# 查看所有包含 ssh 或 tunnel 的服务
Get-Service | Where-Object { $_.Name -like "*ssh*" -or $_.Name -like "*tunnel*" }
# 停止并删除
Stop-Service -Name "你的服务名"
sc.exe delete "你的服务名"

> **⚠️ 注意**：如果服务删除后仍然自动启动，检查是否有计划任务（Task Scheduler）在触发它。

## 第二阶段：恢复本地 Windows 状态

### 2.1 停止并禁用 OpenSSH Server 服务

如果你不再需要本地 Windows 被 SSH 登录，可以停止并禁用 sshd 服务：

powershell

# 停止服务
Stop-Service sshd
# 禁用开机自启
Set-Service -Name sshd -StartupType Disabled
# 确认状态
Get-Service sshd

### 2.2 删除隧道用的公钥

**如果是管理员账户**：

powershell

# 删除整个 administrators_authorized_keys 文件（如果里面只有隧道公钥）
Remove-Item -Path "C:\ProgramData\ssh\administrators_authorized_keys" -Force

**如果是普通账户**：

powershell

# 删除用户目录下的 authorized_keys
Remove-Item -Path "C:\Users\<本地用户名>\.ssh\authorized_keys" -Force

> **💡 建议**：如果该文件里还有其他用途的公钥，不要直接删除整个文件，而是用编辑器打开，**只删除 VPS 的那一行公钥**。

### 2.3 恢复 sshd_config 配置

编辑 `C:\ProgramData\ssh\sshd_config`，将之前为隧道做的修改恢复：

|配置项|恢复为默认值|说明|
|---|---|---|
|`ListenAddress`|删除该行或改为 `0.0.0.0`|之前为了安全改成了 `127.0.0.1`|
|`PubkeyAuthentication`|保持 `yes` 或注释掉|默认允许公钥|
|`PasswordAuthentication`|改为 `yes` 或注释掉|之前为了安全改成了 `no`|

**如果不再需要本地 SSH 服务，可以直接跳过这一步，直接卸载 OpenSSH Server。**

### 2.4 （可选）完全卸载 OpenSSH Server

如果你彻底不需要本地 Windows 被远程 SSH 登录，可以卸载 OpenSSH Server：

powershell

# 卸载 OpenSSH Server
Remove-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
# 删除残留配置目录（谨慎操作）
Remove-Item -Path "C:\ProgramData\ssh" -Recurse -Force

> **⚠️ 警告**：卸载前请确认你不再需要通过 SSH 连接这台 Windows，否则你将无法远程登录。

### 2.5 清理 SSH 客户端已知主机记录

在本地 Windows 的 `C:\Users\<本地用户名>\.ssh\known_hosts` 文件中，删除与 VPS 或 `[127.0.0.1]:2222` 相关的行。

powershell

# 查看 known_hosts 内容
Get-Content C:\Users\<本地用户名>\.ssh\known_hosts
# 用编辑器删除相关行，或直接删除整个文件（会丢失所有已知主机记录）
Remove-Item -Path C:\Users\<本地用户名>\.ssh\known_hosts -Force

## 第三阶段：恢复远程 VPS 状态

### 3.1 恢复 sshd_config 配置

登录 VPS，编辑 `/etc/ssh/sshd_config`，将之前为隧道做的修改恢复：

sh

vi /etc/ssh/sshd_config

找到并修改以下行：

|配置项|恢复为默认值|说明|
|---|---|---|
|`AllowTcpForwarding`|改为 `no` 或注释掉|之前为了隧道改成了 `yes`|
|`GatewayPorts`|保持 `no` 或注释掉|默认就是 `no`，无需改动|
|`PermitListen`|删除该行或注释掉|如果之前添加了限制|
|`Match` 块|删除整个 Match 块|如果之前为用户/IP 做了特殊配置|

**恢复后的推荐配置**：

text

# AllowTcpForwarding no
# GatewayPorts no

### 3.2 重启 VPS 的 SSH 服务

根据 VPS 的系统类型选择命令：

sh

# Alpine Linux / OpenRC
rc-service sshd restart
# SysVinit
service sshd restart
/etc/init.d/sshd restart
# systemd（如果 VPS 实际支持）
systemctl restart sshd
# 通用：重新加载配置而不中断连接
kill -HUP $(cat /var/run/sshd.pid)

> **💥 踩坑提醒**：你的 VPS 是 Alpine/精简系统，没有 systemctl。如果执行 `systemctl` 报 `not found`，请使用 `rc-service` 或 `/etc/init.d/sshd`。

### 3.3 删除 VPS 上用于隧道的密钥

如果你在 VPS 上生成了专门的密钥对用于隧道，可以删除：

sh

# 查看当前密钥
ls -la ~/.ssh/
# 删除隧道专用密钥（谨慎操作，确认不再需要）
rm ~/.ssh/id_ed25519
rm ~/.ssh/id_ed25519.pub

> **⚠️ 警告**：如果这个密钥还用于其他用途（如 Git、其他服务器登录），请不要删除。

### 3.4 清理 VPS 的 known_hosts

sh

# 删除与本地 Windows 或 127.0.0.1:2222 相关的记录
ssh-keygen -R "[127.0.0.1]:2222"

### 3.5 确认 VPS 端口已释放

sh

# 确认 2222 端口不再监听
netstat -tuln | grep 2222
# 或
ss -tuln | grep 2222

如果没有任何输出，说明隧道端口已成功释放。

## 第四阶段：最终验证

### 4.1 在 VPS 上验证

sh

# 1. 确认 2222 端口已关闭
netstat -tuln | grep 2222
# 2. 确认 AllowTcpForwarding 已禁用
sshd -T | grep -i allowtcpforwarding
# 3. 尝试连接（应该被拒绝）
ssh -p 2222 <本地用户名>@127.0.0.1
# 预期输出：Connection refused

### 4.2 在本地 Windows 上验证

powershell

# 1. 确认 sshd 服务已停止或禁用
Get-Service sshd
# 2. 确认 22 端口不再监听
netstat -ano | findstr :22
# 3. 确认没有残留的 SSH 进程
Get-Process | Where-Object { $_.ProcessName -like "*ssh*" }

### 4.3 确认没有残留的 Windows 服务

powershell

Get-Service | Where-Object { $_.Name -like "*ssh*" -or $_.Name -like "*tunnel*" -or $_.DisplayName -like "*ssh*" }

如果输出为空，说明服务已彻底清理。

## 🛡️ 安全提醒

1. **删除公钥前确认**：如果 `authorized_keys` 里还有其他公钥，不要直接删除整个文件。
    
2. **卸载 OpenSSH 前确认**：确保你不再需要远程登录这台 Windows，否则会失去访问途径。
    
3. **保留密钥的备份**：如果删除了密钥，但未来可能还需要，请先备份到安全的地方。
    
4. **检查计划任务**：某些自动重连工具会注册 Windows 计划任务，清理服务后也要检查任务计划程序。
    
5. **重启后验证**：完成清理后，重启本地和 VPS，再次验证所有配置已恢复，确保没有残留服务自动启动。
    

---

## 💎 总结

清理 SSH 反向隧道不仅仅是停止命令，而是一个**双向、多层次的恢复过程**：

1. **进程层**：停止所有隧道进程和服务。
    
2. **配置层**：恢复本地和 VPS 的 `sshd_config`。
    
3. **密钥层**：删除用于隧道的公钥和私钥。
    
4. **网络层**：确认端口已释放，无监听。
    
5. **验证层**：通过尝试连接和检查端口，确认清理彻底。
    

按照本文的清单逐项操作，你的本地 Windows 和远程 VPS 就能安全、干净地恢复到初始状态。
